ESP8266 firmware · man-in-the-middle

A wiretap that sits on the wire between your battery and your board.

Owie splices a tiny WiFi chip into the serial line between a OneWheel's Battery Management System and its motor controller. It reads every packet, rewrites the few that matter, drops the ones that cause trouble, and forwards the rest — unlocking bigger batteries, honest charge readings, and live telemetry over WiFi.

115200 baud UART FF 55 AA framing ~2.2k lines of C++ Wemos D1 Mini Lite

what it buys you

Four problems, solved on the wire

Battery expansion

Any Pint or XR pack, unlocked

Stock firmware pairs the BMS to one controller. Owie rewrites the serial-number packet with a spoofed value, so the controller stops caring which pack it's bolted to.

Honest charge

A percentage you can trust

Modified packs confuse the stock gauge. Owie computes its own state-of-charge and rewrites the percentage packet, so the official app shows the real number.

Error 23

No more phantom fault

Forwarding the status packet during normal riding drives a tally loop in the controller that eventually faults. Owie simply swallows it while everything is healthy.

Visibility

Live telemetry over WiFi

The board hosts its own web page: per-cell voltages, current, temperatures, charge counters, and a raw packet stream for anyone reverse-engineering the protocol.

the tap

How a WiFi chip listens to a differential bus

The BMS and controller talk over an RS485-style differential pair — two wires, A and B, carrying mirror-image signals. The ESP8266 has only one hardware UART, so Owie cheats.

It reads the A line on RX and drives the mainboard's A line on TX at 115200 baud. To rebuild the missing B line, TX is physically jumpered to GPIO4; rise and fall interrupts on that pin bit-bang the inverse level onto GPIO5 — a software half of the differential pair, generated one edge at a time.

the locking trick

Every feature flows through one choke point: the function that writes bytes back to the controller.

// this if-statement is the entire lock if (!Settings->is_locked) { Serial.write(b); }

When the board is locked, the controller simply never hears the battery — so it won't power on. Double-tap the power button within five seconds twice and you're into a settings-wiping recovery mode instead.

The checksum is a plain 16-bit sum of every preceding byte. Because parsers may rewrite the payload, Owie recomputes it before forwarding. Anything that doesn't start with FF 55 AA, or carries an unknown type, is passed straight through untouched — Owie is invisible to traffic it doesn't recognize.

the pipeline

What happens to every byte

The main loop does nothing but pump a cooperative task queue. One of those tasks drains the UART, byte by byte, through this sequence.

Frame

Bytes accumulate in a buffer. If the first three don't match FF 55 AA, or the type is unknown, the whole buffer is flushed to the controller unchanged.

Track

A complete packet is handed to the tracker, which counts it, measures its arrival cadence with Welford's online mean/deviation, and stashes the last valid copy.

Parse & mutate

Type-specific parsers pull out telemetry and, where needed, rewrite the payload (percentage, serial) or mark the packet not-to-forward (status, current).

Re-checksum & forward

Because bytes may have changed, the additive checksum is recomputed, then the packet is written out to the controller — unless a parser vetoed it.

Replay on silence

When the wire goes quiet, any known packet type missing past its timeout (500 ms for status and current, 3 s otherwise) is re-sent from its last good copy, keeping the controller fed.

the fuel gauge

Two bad estimates, fused into a good one

Neither signal alone is trustworthy: voltage sags under load, and coulomb counting drifts over time. Owie tracks a moving window built from both.

Signal A · voltage

Lowest cell → SOC

The minimum cell voltage is low-pass filtered (a 2nd-order Butterworth with a ~400-second period) then mapped through a lithium open-circuit-voltage table spanning 2.7 V to 4.2 V.

Signal B · charge

Current → milliamp-seconds

Each current reading is integrated over the time since the last one, accumulating charge pulled from — and pushed back into — the pack.

the tracked windowSOC interpolation

Reported SOC is just the current charge position interpolated between the window's endpoints. When the voltage estimate and the coulomb estimate disagree by more than about 3× near the extremes — below 10%, or above 90% while charging — voltage wins and drags the window back into line. The whole window is saved to flash so it survives a power cycle.

boot, storage & recovery

The parts that keep it alive

Boot

Cooperative, no RTOS

Settings load, the board decides whether to lock, then either the relay or recovery mode starts. The loop only ever pumps the task queue.

Recovery

The two-tap escape hatch

A counter rises each boot and resets after five seconds. Two quick power cycles leave it high, booting an open Owie-recovery AP that wipes settings and serves only the flasher.

Settings

Wear-leveled protobuf

Config is a nanopb message written across four rotating flash sectors, length-prefixed, and reset to defaults if it ever fails to decode.

network & delivery

A whole web app in flash

There's no filesystem. The build minifies each HTML page and bakes it into the binary as a PROGMEM byte array, with %PLACEHOLDER% substitution filled in live from relay state.

Access

Captive portal over SoftAP

The board is always its own access point (Owie-XXXX), optionally joining your home WiFi too. A wildcard DNS server points every hostname at the board, so connecting drops you straight on the status page.

Pages

Status, battery, monitor, OTA

Endpoints cover live status (polled as JSON), fuel-gauge resets, WiFi and AP settings, packet statistics, a raw-packet WebSocket for protocol sleuthing, locking, and browser-based firmware updates.

building it yourself

Two commands

# host-native unit tests (lib/bms core) pio test -e native # build firmware for the Wemos D1 Mini Lite pio run -e d1_mini_lite_clone

The lib/bms/ core is deliberately hardware-independent so it compiles and runs under Unity on your laptop with a fake clock and scripted packet streams. CI runs both on every push; tagged releases publish firmware.bin.
